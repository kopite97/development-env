# 백엔드 개발 문서

기준일: 2026-09-10. 안정화 1~~15번 중 구현 완료된 기능(1~~15, 14번 포함)을 현재 작업 트리와 대조했다. 서버·로그인·HTTP 연동은 아직 구현되지 않았다. 이 문서 묶음은 **여러 사용자가 로그인하고 각자 독립된 개인 작업실을 사용하는 서비스**를 위한 구현 기준안이다.

새 구현에서는 구현 명세가 API의 기준이고, 개발 지침은 실행 방법, 차이 분석은 근거다. 기존 계약과 다르면 새 명세를 따른다. 원본은 과거 설계를 확인할 수 있도록 보존했다. API는 아직 배포되지 않았으므로 이 변경이 실제 서버 API 버전 업그레이드를 의미하지 않는다. 구현 시 새 명세를 OpenAPI로 옮기고 계약 테스트로 고정한다.

## 제품 범위

- 필수: 로그인/로그아웃/세션 복원, 사용자별 개인 작업실, 프로젝트·작업·일지·링크·마일스톤·홈 배치 저장, 검색·통계, 기기 간 동일 데이터 조회.
- 각 사용자의 업무 데이터와 홈 설정은 다른 사용자에게 공개되지 않는다. 작성자 외 공동 편집·초대·공유 링크는 초기 범위에 없다.
- 여기서 개발 환경 설정은 현재 UI의 프로젝트/목표/작업/일지/링크/위젯 구성을 뜻한다. 원격 IDE, 컨테이너 실행, 코드 저장소 생성, 실제 배포 실행은 별도 제품 범위다.
- 접근성·URL 이동·편집 취소는 프론트 책임을 유지한다. 운영 위젯은 여전히 데모이며 서버 연동 성공으로 오인시키지 않는다.
- 새 계정은 빈 업무 데이터와 기본 위젯 배치로 시작한다. 현재 개인의 데이터나 데모 프로젝트를 모든 사용자에게 복제하지 않는다.

## 설계 가정과 착수 전 결정

사용자별 격리는 요청에서 확정된 요구다. 아래는 구현을 진행할 수 있도록 정한 **기본 제안**이며 현재 구현 사실이나 사용자 확정 선택이 아니다.

| 항목           | 기준안                                                            | 변경 시 영향                                                       |
| -------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------ |
| 작업실         | 사용자당 개인 작업실 1개                                          | 여러 작업실/팀을 추가하면 API 경로·멤버십 권한부터 재설계          |
| 인증           | OIDC 제공자 로그인 + 서버 세션 쿠키, 첫 로그인 시 계정 생성       | 직접 비밀번호 방식은 가입/인증/재설정/비밀번호 저장 정책 추가 필요 |
| 배포           | HTTPS 한 origin에서 SPA와 `/api` 제공                             | origin 분리는 CORS·쿠키·CSRF 설정과 테스트 추가                    |
| 기술 스택      | 특정 언어/프레임워크 미지정, 트랜잭션 가능한 관계형 저장소를 전제 | 제품 요구/REST 계약은 유지하고 저장소 제약을 동등하게 구현         |
| 기기 동시 사용 | revision 충돌 감지, 자동 덮어쓰기 없음                            | 실시간 협업·충돌 자동 병합은 별도 범위                             |

인증 제공자/실제 스택·DB/배포 도메인, 가입 허용 정책, 세션 수명·쿼터·백업 보존 및 계정 삭제 정책은 배포 전에 정한다. 이 선택이 미정이어도 도메인 스키마, 소유권 검사, REST DTO, 두 사용자 격리 테스트부터 구현할 수 있다. 인증 제공자별 callback 설정은 선택 후 공식 문서로 확정한다.

현재 구조는 [프론트 아키텍처](../../architecture/frontend.md), 남은 UI 작업은 [안정화 계획](../../plans/PLAN-0003-frontend-stabilization.md)을 참고한다.
