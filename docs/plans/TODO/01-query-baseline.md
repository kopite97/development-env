# 01. 조회 성능 측정·API 계약 확인

진행 상태와 실행 PLAN: [추적 목록](readme.md).

- 목적: 중복·순차 요청과 화면 대기의 원인을 확인한다.
- 범위: 홈↔프로젝트 목록↔상세, 홈↔할 일, 편집창 열기.
- 작업: 기존 Swagger와 실제 응답을 대조하고 변경 번호·커서·생성 replay 계약을 정리한다.
- 측정: 최초 방문·재방문·변경 후 방문의 요청 수, 전송량, API 대기, 데이터 표시 시간. 실행 환경과 데이터 규모도 기록한다.
- 완료 기준: 재현 가능한 기준 자료, 우선 병목, 02의 개선 목표가 정리된다.
- 제외: 캐시 동작 변경, 라이브러리 전환, 운영 부하 테스트.

- 완료: 2026-09-16. [PLAN-0021 결과·재현 자료](../../reviews/plan0021-query-baseline/readme.md). 190개 표본으로 프로젝트 재방문 개선 목표를 확정했으며 앱 최적화 구현은 후속 계획에서 진행한다.
