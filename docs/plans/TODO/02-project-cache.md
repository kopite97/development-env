# 02. 프로젝트 목록·상세 캐시 재사용

진행 상태와 실행 PLAN: [추적 목록](readme.md). 선행: 01.

- 목적: 변경 없는 목록↔상세 왕복에서 데이터를 재사용한다.
- 작업: 화면 이탈 시 캐시 삭제를 정리하고 구독 해제·요청 취소와 구분한다.
- 작업: 캐시 재사용 조회와 강제 재조회를 분리하고 유효 시간·미사용 캐시 정리 정책을 적용한다.
- 범위: 공통 Query는 프로젝트 시범에 필요한 만큼 개선하며 다른 기능의 기본 동작을 유지한다.
- 장기 적용: [PLAN-0022](../PLAN-0022-project-query-cache.md)에서 세션별 공통 생성 모듈·필수 정책 선언·빌드 검사를 마련한다. 신규 조회는 이 경로를 사용하고 기존 미전환 기능은 명시적 예외로 추적한다.
- 검증: 요청 감소, 페이지·스크롤 복원, 저장·보관·분류 변경, 충돌 복구, 계정 전환과 지연 응답.
- 완료 기준: 01 대비 재방문 요청이 줄고 기존 데이터 정합성 검증을 통과한다.
- 제외: 모든 기능 일괄 전환, 인증 확인·저장 결과 재확인 조회의 무조건 생략.

## 01 측정으로 확정한 최소 범위

- [기준 결과](../../reviews/plan0021-query-baseline/readme.md): 목록 복귀마다 GET 1건, 누적 25→20개·스크롤 1771→0px 초기화가 10/10회 발생했다.
- 목표: 유효 기간 내 변경 없는 목록 복귀 GET 0건, 누적 페이지·스크롤 보존. 상세 재방문은 프로젝트 GET 1→0건을 목표로 하되 카테고리 1건은 03에서 다룬다.
- 홈에서 첫 프로젝트 목록 진입은 이미 0건이므로 유지한다. TTL·미사용 캐시 회수는 프로젝트에 한정해 정식 PLAN에서 명시한다.
- 변경·만료·강제 재조회·revision 감지·충돌 복구·세션 격리를 보존하고 같은 시나리오를 10회 이상 재측정한다. 아직 구현은 시작하지 않았다.
