# PLAN-0021 조회 성능 기준 측정

2026-09-16 · [실행 계획](../../plans/PLAN-0021-query-performance-baseline.md) · Session 1~3 완료.
앱·백엔드 소스, 의존성, 운영 설정은 변경하지 않았다. 측정 도구와 결과 문서만 추가했다.

## 결론

- 우선 대상은 **프로젝트 목록·상세 재방문**이다. 목록 복귀 시 1회 재조회하며 누적 25개가 20개로, 스크롤 1771px가 0px로 돌아가는 현상이 10/10회 재현됐다.
- 홈→작업 보드→홈의 홈 재방문과 작업 보드 재방문은 이미 **추가 API 0건**이다. 모든 페이지 이동이 서버 재조회를 일으키는 것은 아니다.
- 프로젝트 편집창은 열 때마다 카테고리를 1회 조회한다. 일지 편집창 첫 진입의 프로젝트 재조회도 TODO 03 대상이다. 할 일·일지 편집창의 단순 재열기는 이미 0건이다.
- 저장은 CSRF 조회·PATCH·상세 재확인·연관 데이터 갱신을 포함한다. 이를 불필요한 중복으로 간주하지 않는다.

## 조건·지표 해석

- Windows 11, i5-1335U, Chromium 153 headless, 1440×1000, Node 24.14.0. `tsc -b && vite build` 산출물을 Vite preview로 실행했다. StrictMode 개발 빌드 측정이 아니다.
- 기존 Spring Boot 4.1.1 / Java 21 백엔드와 새 PostgreSQL 16.4 Testcontainers DB를 사용했다. 로컬 OIDC 공급자로 실제 세션 로그인을 완료했다. Redis·mock 업무 API는 사용하지 않았다.
- 사용자 1명, 카테고리 3개, 프로젝트 25개, 할 일 30개(상태별 10), 일지 3개, 링크 1개. 연결 데이터는 두 번째 목록 페이지에 있는 Project 01에 속한다. 기본 홈 위젯 설정을 사용했다.
- 최종 환경은 예비 측정 후 새 DB로 재시작했다. 데이터 준비·계약 검증과 첫 전체 실행 1회는 제외하고 이후 10회만 집계했다. 각 회는 새 브라우저 context/문서, 회 안에서는 동일 세션·메모리로 이동한다. DB 행 수는 동일하며 설명 저장으로 revision만 진행한다.
- localhost, 네트워크/CPU 제한 없음, 사용자 흐름은 순차 실행하며 페이지 안의 API 병렬 요청은 그대로다. 업무 응답은 no-store. Render RTT, TLS, 실제 사용자 분포, 대규모 데이터, 다중 사용자, 모바일은 미측정이다.
- `visibleMs`: 자동화 동작 시작부터 화면별 주요 DOM 조건 충족 후 두 animation frame까지. 홈은 사용자·최근 일지·할 일, 목록은 행 수, 상세는 제목·편집 가능 상태, 편집창은 옵션/대화상자, 저장은 변경 설명을 확인했다. **전체 위젯 완료나 순수 렌더링 시간은 아니며** Playwright 클릭 대기·스크롤·검증 비용도 포함한다.
- 주요 표시 후 API 진행 상태가 200ms 안정될 때까지 요청을 수집했다. 이 안정 대기는 visibleMs에 포함하지 않으며 `networkidle`만으로 완료를 판정하지 않았다. 측정 사이 준비 이동·편집 입력·추가 페이지 펼치기는 구간별 요청 합계에 포함하지 않는다.
- 응답 bytes는 Playwright의 API 응답 본문+헤더 크기이며 요청 본문·정적 자산·TLS 비용은 제외한다. 원자료에 시작 offset, 종료까지 시간, TTFB, 마지막 API 종료와 주요 표시 사이 차이를 저장했다. 음수 차이는 주요 데이터가 나머지 API보다 먼저 표시됐다는 뜻이다. 양수도 순수 React 렌더링 시간으로 해석하지 않는다.
- 예를 들어 첫 유효 홈 표본은 인증 요청 약 133ms 시작, 설정 등 약 223ms, 위젯 약 334ms에 시작했다. 일부 선행 의존성이 있으나 나머지는 병렬이다. 서버 DB 시간과 네트워크·프록시·브라우저 대기를 분리 측정하지 않았으므로 DB 병목이나 운영 p95를 주장하지 않는다.

## 재현·검증·원자료

같은 sibling `../backend`, Java 21, Docker Desktop, 설치된 Chromium이 필요하다. 테스트 서버는 4175/18080/18999 포트와 빈 전용 DB만 사용한다. `.env` 대신 로컬 값을 주입한다.

```powershell
npm run build
node tools/query-baseline-environment.mjs
```

`BASELINE_READY` 이후 다른 터미널에서 `node tools/query-baseline.mjs`를 실행한다. 종료 시 환경 터미널에서 Ctrl+C로 소유 서버와 테스트 DB를 정리한다. Java 경로가 다르면 `BASELINE_JAVA_HOME`을 지정한다. `--pilot`은 결과를 git 제외 경로에 저장한다. 캐시 개선 후에는 도구의 현재 페이지/옵션 수 기대값도 새 동작에 맞춰 검토해야 한다.

- 도구: [환경 실행](../../../tools/query-baseline-environment.mjs), [측정](../../../tools/query-baseline.mjs).
- 근거: [API 계약·소스 경로](api-contract.md), [환경·버전](metadata.json), [HTTP 검증](checks.json), [요약](summary.json), [표본](samples.json), [요청별 타이밍](requests.json).
- `npm run build`, 도구 구문 검사, 실제 11회 실행(1회 제외), 요약 재계산을 통과했다. 문서 링크·diff 검사는 PLAN 실행 기록에 남긴다.
- UUID·커서는 합성 별칭으로 치환했고 Cookie·세션/CSRF/OAuth 값·storageState·업무 응답 본문은 저장하지 않았다. 검증 파일에는 합성 집계 값만 남겼다.
- 예비 도구 실행 1회가 정상 저장 알림을 오류로 취급해 중단됐다. 허용 알림 판정을 수정하고 예비 실행 성공 및 새 환경의 최종 11회 성공을 확인했다. 중단 표본은 결과에 포함하지 않았다.
