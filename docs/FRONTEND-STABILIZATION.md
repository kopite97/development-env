## 구조 정리 — 완료

2026-09-09 요청 반영. App.tsx는 Provider·레이아웃·페이지 선택기 조합만 담당하도록 축소했습니다. 페이지 5개, 공통 레이아웃, 기능별 콘텐츠와 저장 Provider, 위젯 등록부를 분리했습니다. 전역 CSS도 기본·공용 UI·레이아웃·배치·기능별·반응형 파일로 나눴습니다. 기존 저장 키와 화면 동작은 유지합니다.

새 파일의 책임과 확장 규칙은 [ARCHITECTURE.md](ARCHITECTURE.md)에 정리했습니다. URL 라우팅(14번), CRUD 등 대기 항목은 이번 구조 정리에 포함하지 않았습니다.

## 1~4번 검증 기록

완료일: 2026-09-09. 현재 9~17번은 대기합니다.

### 구현 내용

1. 사이드바에 독립적인 세로 스크롤을 적용하고 자식 요소가 낮은 창에서 압축되지 않게 했습니다. 프로필을 포함한 전체 영역에 접근할 수 있습니다.
2. 공통 Board에 태스크 드래그를 추가했습니다. 홈과 별도 작업 보드에서 열 사이 이동, 빈 열 드롭, 드롭 대상 강조, 로컬 저장을 지원합니다. 태스크 전용 드래그 데이터와 이벤트 전파 제어로 위젯 배치 이동과 분리했습니다. 키보드·터치 환경에서는 기존 상태 선택 상자를 사용할 수 있습니다. 같은 열 안의 수동 순서 변경과 서로 다른 보드 사이 드래그는 이번 범위에 없습니다.
3. 개발일지 페이지 상단에 '일지 작성'을 추가했습니다. 공용 Modal·Field·Button으로 제목(최대 120자), 프로젝트, 본문(최대 20,000자)을 입력하고 필수값을 검증합니다. 일지는 고유 id와 작성 시각을 가지며 `devspace.journals.v1`에 저장됩니다. 목록과 홈 최근 3건에 반영되고 새로고침 후에도 유지됩니다. 생성 후에는 필터·검색을 초기화해 새 글이 보이게 합니다. 11번 중 날짜 표시·생성 시 최신순 정렬의 기반은 함께 적용했지만 수정·삭제는 대기입니다.
4. 저장 어댑터는 저장 성공 후에만 상태를 반영하고 성공 여부를 반환합니다. 배치·일지 저장 실패 시 편집 내용을 유지하여 같은 저장 버튼으로 재시도합니다. 태스크 저장 실패 시 마지막 저장 상태를 유지하고 상태 선택 또는 드래그를 다시 할 수 있습니다. 공통 `useUnsavedChanges`로 배치·위젯 설정·일지의 미저장 변경을 보호합니다. 취소·Escape·배경 클릭 시 변경 폐기를 확인하고, 새로고침·창 닫기에는 beforeunload를 등록합니다. 배치 편집 중 메뉴 이동 차단도 유지합니다.

공용 모달의 이름을 연결하고 내부 여백 클릭은 배경 클릭으로 처리하지 않게 했습니다. Escape에서 폐기를 거절하면 브라우저 기본 닫기도 방지합니다. 15번의 모바일 메뉴 초점 관리·진행률 이름 등 나머지 작업은 남아 있습니다.

### 검증 결과

- `npm run build`: 통과.
- `npm test`: 단위 테스트 4개 통과.
- `npm run test:e2e`: Chromium 브라우저 테스트 9개 통과(기존 3개 + 안정화 6개).
- 사이드바: 1366×768, 1280×600, 844×390, 390×500에서 하단 프로필을 스크롤해 화면 안에 놓고 실제 클릭 확인.
- 태스크: 실제 dragTo로 홈·별도 보드의 상태 변경, 빈 열 이동, 위젯 순서 유지, 배치 취소 후에도 작업 변경 유지, 새로고침 유지 확인.
- 일지: 필수값 검증, 생성, 목록·홈 반영, 상세 본문, 새로고침 유지 확인.
- 오류: localStorage에 QuotaExceededError를 발생시켜 배치·일지 재시도와 태스크 저장 실패 시 상태 유지 확인.
- 편집 보호: 취소 확인에서 계속 편집/폐기 선택, Escape 취소 시 일지 입력 유지, dirty 상태의 beforeunload 이벤트 차단 및 취소 후 리스너 해제 확인.

beforeunload 안내의 표시·문구는 브라우저 정책에 따릅니다. 브라우저 강제 종료나 운영체제 종료까지 초안을 복구하는 자동 임시 저장은 이번 범위에 포함하지 않습니다. 터치 드래그는 후속 검토 항목이며 상태 선택으로 동일한 변경을 수행할 수 있습니다.

## 5~6번 결과

- 완료: 태스크 생성·상세 편집·휴지통 삭제/복구, 프로젝트 등록·편집·보관/해제와 로컬 저장.
- 프로젝트 이름·분야 변경 시 연결된 작업·일지도 반영됩니다. 보관해도 작업·일지는 유지됩니다. 프로젝트 선택은 공용 컴포넌트를 사용합니다.
- 검증: 빌드, 단위 테스트 7개, 브라우저 테스트 12개 통과. 기존 저장 데이터 호환과 저장 실패 시 입력 유지 확인.

## 7~8번 결과

- 프로젝트 통계는 검색과 독립적으로 선택 분야와 현재/보관 목록에서 계산합니다. 작업 통계는 보관 프로젝트의 작업도 포함한 해당 분야 전체이며 삭제된 작업은 제외합니다. 검색 결과 수는 별도로 표시합니다.
- 홈·프로젝트·작업 보드·개발일지·자료실에 공용 빈 상태와 검색·분야 초기화를 연결하고, 기존 생성 기능이 있는 화면에는 추가 버튼을 연결했습니다. 링크 추가는 10번에서 진행합니다.
- 검증: 빌드, 단위 테스트 7개, 브라우저 테스트 14개 통과. 변경 파일 포맷 통과. 전체 포맷 검사는 기존 미수정 파일의 문제로 실패했습니다.
